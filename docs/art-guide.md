# Арт-гайд: файл зверей, слои, палитры, анимации

Внешность питомцев собирается из одного Inkscape-файла **`art/zveri.svg`**.
Импортёр компилирует его в `shared/petArt/generated/zveri.ts`. Этот модуль
используют игра и картинка NFT, поэтому они всегда совпадают.

## 1. Где файл и как работать, пока проект запущен

**Источник правды — `art/zveri.svg` в проекте.** Лучше всего открывать в
Inkscape прямо его, а не копию на рабочем столе. Тогда файл один, он
попадает в git, и ничего не нужно копировать.

```bash
cd backend
npm run art:watch                                   # следит за art/zveri.svg
npm run art:watch -- "C:/Users/Asus/Desktop/Звери.svg"   # или за файлом в другом месте (копирует в art/)
```

С запущенным `art:watch`:

1. Художник сохраняет файл в Inkscape (Ctrl+S).
2. Импортёр за ~0,5 с пересобирает арт и печатает отчёт по слоям.
3. Фронтенд обновляется сам (Vite HMR), бэкенд перезапускается сам (`tsx watch`).
4. Результат виден сразу на **http://localhost:5180/lab** (Art Lab, только в
   dev). Там можно вылупить случайного зверя, выбрать тир палитры,
   настроение и стадию роста, посмотреть все варианты всех слоёв и сыграть
   в тренировки без наград.

Разовый импорт без слежения — `npm run art:import`. HTML-галерея для
отправки команде — `npm run art:gallery`.

**Уже вылупившиеся питомцы не меняются**: их внешность хранится в базе
(`Pet.look`). Новые варианты получат только новые звери. Чтобы посмотреть
новинку сразу, используйте `/lab`.

## 2. Как называть слои

```
Человеческое имя [key] @роль @роль
```

| Часть | Пример | Зачем |
|---|---|---|
| `[key]` | `Уши [ears]` | **Стабильный ключ слоя.** Хранится у питомцев, им называется трейт в NFT. Латиница, без пробелов. Слой можно переименовывать как угодно, если `[key]` не меняется. |
| `@роль` | `Очки [glasses] @head @blink` | Как слой двигается в анимации (см. §5). Без ролей работают значения по умолчанию для известных ключей; новый слой без ролей двигается вместе с телом. |
| `_` в начале | `_эскизы`, `_pivots` | Служебный слой, **никогда не рисуется**. Подходит для набросков, референсов и точек вращения. |

Ключи сейчас: `tail legs feet body belly arms ears head muzzle eyes iris
highlight eyelids nose mouth hair horns`. Слой без `[key]` пока ищется в
таблице русских имён (`SLOT_KEYS` в [import-art.ts](../backend/scripts/import-art.ts)).
Это работает, но с `[key]` надёжнее: переименование слоя ничего не сломает.

**Новый тип части** (например, очки): создайте слой `Очки [glasses] @head`
в нужном месте стопки и сохраните. Код трогать не нужно.

### Варианты внутри слоя

* **Видимые** сейчас объекты слоя вместе — **один** вариант.
* **Каждый скрытый** объект или группа — **отдельный** вариант.
* Поэтому **скрытую пару (левое + правое) обязательно группировать (Ctrl+G).**
* Подписи групп (Object Properties → **Label**, например «Рожки-спиральки»)
  становятся названиями трейтов в NFT и в карточке. Без подписи показывается `#1`, `#2`…
* **Не удаляйте** объекты, которые уже выпадали питомцам. Группировать,
  двигать и перекрашивать можно: старые питомцы находят свой вариант по
  id объектов внутри группы. Именно так пережили вашу перегруппировку уши
  `path73+path73-2` → `g1`.

### Для лёгкого и быстрого файла

* Импортёр сам выкидывает неиспользуемые градиенты, служебные атрибуты
  Inkscape и округляет координаты до 0,001.
* Path effects (скругления и т.п.) лучше применять: **Path → Object to Path**.
* Растр, текст, фильтры и маски не использовать: они плохо перекрашиваются
  и тяжело рендерятся.
* Используйте **цвета палитры файла**, а не случайные оттенки: каждый новый
  цвет — это ещё одна точка на шкале яркости (см. §3).

## 3. Цвета и палитры

**Как перекрашивается тело.** Каждый цвет файла (кроме чёрного, белого и
радужки) получает позицию по яркости: `t = 0` — как самый светлый
референс `#f3e79b`, `t = 1` — как самый тёмный `#5c53a5` (`RAMP_LIGHT` и
`RAMP_DARK` в импортёре). У питомца есть палитра — шкала от светлого к
тёмному, и каждый цвет файла берёт цвет шкалы в своей точке `t`. Живот и
мордочка остаются светлыми, шерсть тёмной. Новые цвета в файле
**не сдвигают** старые: позиция зависит только от яркости самого цвета.

**Тиры палитр** — генерируются процедурно, поэтому их бесконечно много
([palettes.ts](../shared/petArt/palettes.ts)):

| Тир | Как устроена | Пример имени | Доля (в среднем) |
|---|---|---|---|
| Обычная | оттенки **одного** цвета; сдвиг тона ±6°, приглушённая, обычная или яркая | «Dusty Jade», «Vivid Orchid» | ~86% |
| Редкая | **два** цвета: светлая половина одного тона, тёмная другого | «Azure & Scarlet» | ~12% |
| Легендарная | **три** цвета: светлая, средняя и тёмная трети, всегда сочные | «Violet · Amber · Sky» | ~2% |

Шанс тира зависит от редкости DNA (`PALETTE_TIER_ODDS`): у MYTHIC
легендарная палитра в 60% случаев, у COMMON — в 1%. Палитра сохраняется у
питомца целиком, поэтому правка генератора не перекрашивает старых зверей.

**Аура** — слой `AURA` (ключ `aura`), самый нижний в стопке. Его
цвета **не** из палитры тела: импортёр превращает стопы его градиента в
токены, а рендер подставляет цвета стихии питомца
([aura.ts](../shared/petArt/aura.ts)): FIRE — ваши исходные жёлто-оранжевые,
WATER, EARTH, AIR, LIGHTNING, SHADOW, LIGHT, VOID — свои пары цветов.
Слой рисуется **только у питомцев с аурой** из DNA (~1%) и мерцает.
Варианты формы ауры можно добавлять так же, как другие варианты слоя.

**Радужка** — полностью случайная (не из палитры). С шансом 50% оба
глаза одного цвета, иначе — гетерохромия.

## 4. Шансы

| Что | Шанс | Где |
|---|---|---|
| Обычный слой | вариант равновероятно | `look.ts` |
| Рога, хвост | COMMON 8% → MYTHIC 60% (в среднем ~10%) | `OPTIONAL_SLOT_CHANCE` |
| Гетерохромия | 50% | `HETEROCHROMIA_CHANCE` |
| Тир палитры | см. §3 | `PALETTE_TIER_ODDS` |

## 5. Анимации

Анимации — это CSS внутри SVG, поэтому они работают везде, где показан
питомец (карточки, профиль, игры), без JavaScript. Картинка NFT статична.
У каждого питомца свой темп и фаза, поэтому они не двигаются синхронно.

| Настроение | Когда | Что делает |
|---|---|---|
| `idle` | по умолчанию | дышит, покачивает головой, моргает, иногда шевелит ушами, виляет хвостом, слегка двигает руками |
| `happy` | после кормления и игры, удачного удара или прыжка в тренировке | подпрыгивает, быстро виляет хвостом, шевелит ушами |
| `sleep` | после отдыха; если энергии < 15 | глаза закрыты, медленно дышит, голова наклонена, над головой «z z z» |
| `run` | в играх (Block Runner, Sol Catcher, карточки игр) | переваливается и подпрыгивает на каждом шаге, ноги поднимаются по очереди, руки машут, хвост виляет быстро |

**Роли слоёв** (`@роль` в имени слоя):

| Роль | Движение | Вокруг какой точки |
|---|---|---|
| `@head` | покачивание головы | `neck` |
| `@ears` | шевеление | `head` |
| `@hair` | подпрыгивание чёлки | `head` |
| `@blink` | моргание (сжатие по вертикали) | `eyes` |
| `@tail` | виляние | `tail` |
| `@arms` | покачивание рук; при беге — левая и правая по очереди | `body` |
| `@stride` | шаг: левая и правая половина слоя поднимаются по очереди | `hips` |
| `@aura` | мерцание пламени | `ground` |

По умолчанию: голова, мордочка, нос, рот, рога → `@head`; уши → `@head @ears`;
глаза, радужка, блик, веки → `@head @blink`; прическа → `@head @hair`;
хвост → `@tail`; ручки → `@arms`; ножки и лапки → `@stride`; аура → `@aura`.

**Как работает бег без отдельных рисунков ног.** Обе ноги нарисованы в
одной группе, поэтому на время бега слой рисуется дважды: один раз
обрезанным по левой половине холста, второй — по правой. Половины
двигаются в противофазе. Граница половин — x точки `hips`. Если ноги
нарисованы не симметрично относительно центра, передвиньте кружок `hips`.

**Точки вращения.** Создайте скрытый слой **`_pivots`** и положите в него
маленькие круги с метками (Label) `neck`, `head`, `eyes`, `tail`, `body`,
`ground`, `hips`. Их центры станут точками вращения. Без этого слоя используются
значения по умолчанию для текущего файла: шея (252, 330), центр головы
(252, 201), линия глаз (254, 191), корень хвоста (212, 398). Если
поменяется положение хвоста или головы, достаточно передвинуть кружок.
